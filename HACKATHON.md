# Rights Desk — PayPal AI Hackathon handoff

The demo story is **recorded permission → clear comparison → approved change → verified payment**. A creator supplies an existing permission and a description of the proposed use. Rights Desk shows supporting passages, asks about missing scope one question at a time, and prepares a change for creator review. The creator sets the additional fee. The buyer accepts the exact approved change before PayPal Sandbox checkout, and the resulting receipt stays with that change in the case.

## Run the actual demonstration

To record the complete payment flow, choose **Start a permission review** on My desk. Use fictional or authorized records. For a walkthrough that ends at the preview, open **How Rights Desk works** and choose **Explore the workflow**.

1. Install Node.js 22 or newer. No npm install is needed. ImageMagick, ExifTool, and C2PA tools support optional evidence features; the permission-comparison demo does not require them.
2. Start Ollama and install the configured model. The default is `gemma3:4b`; `OLLAMA_MODEL` can select a different installed model. Run `ollama serve` if the desktop app is not already serving, then `ollama pull gemma3:4b`.
3. In PayPal Developer, select Sandbox and use an existing or new app associated with a Sandbox business account. Supply its client ID and secret privately in the server environment, or use the macOS Keychain references documented in README. A separate Sandbox personal account acts as buyer. Never put actual credentials in source, ignored repository files, screenshots, video, public README text, or Devpost text.
4. Run `npm run check` and `npm test`, then `npm run readiness`, `npm run verify:permissions`, and `npm run verify:paypal`. The last command checks authentication only. Launch `npm start`. `GET /api/status` should report `paypalConfigured:true` and `ollamaAvailable:true`; this reports availability, not a verified payment.
5. Open `http://localhost:5188/#protect` and start a permission review from My desk. Supply a work title and medium. Use fictional sample text or authorized records for the recording. To start from a contract, attach it, choose **Pull terms from contract**, and review the draft against the cited pages.
6. Paste the relevant existing permission, then describe the proposed use. A clear example is website use for one year in the United States, with paid ads excluded, followed by a request to add paid Instagram advertisements. Run the real comparison and show the `ollama` result with passages from both records. The server checks quotations against their supplied source texts.
7. Answer missing scope questions one at a time. Show that duration and territory are still questions when the proposed use omits them. Back, leave for later, and saved drafts support an unhurried review. For the completed example, explicitly enter “Six months from payment confirmation” and “United States only.” Nothing silently defaults to permanent or worldwide permission.
8. Review and edit the proposed purpose, channels, duration, territory, and conditions. Set the additional fee yourself, confirm the original permission and your authority, and review the exact buyer preview before creating an offer. The fee is creator-set; the comparison model does not determine damages or market value.
9. Copy the approved buyer link and open it in a separate browser session on the same computer. The buyer sees the work identity, approved additional permission, fee, terms, and fingerprints. The original permission text, private messages describing the proposed use, comparison passages, case notes, and supporting files stay private. Keep the checkout in the same buyer browser and localhost origin through the PayPal return.
10. As the test buyer, enter a fictional licensee name and accept the exact approved change. Continue to PayPal Sandbox with the separate personal buyer account. Rights Desk verifies the order, offer reference, completed capture, currency, and amount before issuing the receipt, which is available in Records and the case.
11. Open **Records** to show the saved permission receipt, then return to the creator's case if needed. Both views retain the paid change. The receipt must retain the same approved scope, fee, terms version `rights-desk-permission-change-v1`, and change fingerprint accepted before checkout. Later comparisons or edits to case notes must not rewrite it. This change covers its stated additional permission; it does not settle earlier claims or deliver private case files.
